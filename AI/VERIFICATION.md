# Verification

## The checks

| Check | How | What it proves |
| --- | --- | --- |
| Build | Visual Studio, `dotnet build`, or `"<Visual Studio>\MSBuild\Current\Bin\MSBuild.exe" Forge.Blazor.sln -restore -p:Configuration=Release -m` in the solution folder | Every target of every project compiles, and the packages are written. In the solution folder this rewrites the packages in `..\.Documents\`: to keep them, build a copy of the solution (with `..\.Documents\Forge.snk`; delete the copy afterwards, the key has no password), or pass `-p:PackageOutputPath=<another folder>\`. Since 2026-11-15 `dotnet build Forge.Blazor.sln -c Release` works as well. .NET Framework MSBuild needs the full paths under 260 characters. |
| Package contents | Open the `.nupkg` as a zip | `lib/<target>/` for every target; each `lib/<target>/Forge.Security.Jwt.Client.xml` parses and belongs to its target (its member count; the `netstandard2.0` file may differ from the .NET ones); the `.nuspec` dependency groups match `DESIGN.md`; `README.md`, `LICENSE` and `logo.png` at the root, `<icon>logo.png</icon>`; the `.nuspec` repository commit is the commit the package was built from |
| Vulnerable packages | After a restore: `dotnet list <project> package --vulnerable --include-transitive` | No package with a known vulnerability reaches the consumers |
